# effect-review · 效果复盘

Agent 的自我验证：每天派新活之前，先复盘昨天派的活儿干得怎么样——昨日新发券的核销率、差评顾客今天有没有追加投诉/回访转好评。

这是"持续学习"维度的实证组件：不是概念，是每晚真实跑在生产环境的一行复盘。

## 搬走复用

1. 两种用法任选：
   - 整个目录作为云函数部署，`{ shopId }` 入参，返回 `{ review, pushText }`
   - 只搬三个函数（`yesterdayReview` / `injectReview` / `reviewPushText`）内嵌进你的主控函数——**推荐**，省一次函数调用
2. 输入：`coupons`（昨日新发）、`feedbacks`（昨日差评 + 今日动向），都在你自己的数据库里
3. 输出：结构化复盘（issued/redeemed/rate/badCount/followBad/followGood）+ 人话复盘行
4. 通用性：任何"策略→执行→次日自动验证→滚动调整"的运营 Agent 都能套——餐饮发券、美业召回、零售促销，只是集合名不同

## 典型闭环（我们自己的用法）

```
每晚主控 Agent：
① effect-review 复盘昨日（本组件，纯规则不烧 LLM）
② 复盘结论注入 LLM 上下文 → 今日建议接着复盘迭代
   （核销率不足 30% → 强制给出券策略调整方向）
③ 复盘行写进《每日经营建议》第一条 → 老板看得到
④ 复盘字段写进 agentLog → 可审计、可答辩
```

## 注意

- **别改成 LLM 实现**——纯规则就是这个组件的意义：零成本、每晚全量跑、结果可复算
- 昨日没发券也没差评时返回空复盘（text 为空串），调用方不要硬显示一行
- 差评顾客判定依赖 openid 一致；匿名评价无法追踪动向，属正常降级
