# 换皮指南：30 分钟复刻到你的行业

这套模板的业务逻辑与行业解耦，换行业只需改 4 处。**以 餐饮 → 花店 为例**，其他行业（茶饮/汽修/美业/烘焙）同理。

## 第 1 处：行业知识包（10 分钟）

改 `examples/seedKb.js` 里的知识条目，格式不变：

```js
{ industry: '花店', scene: '好评裂变',
  tips: ['客户晒图率最高的是配送那一刻，券文案引导晒花束图', ...] }
```

写完重新云端测试跑一次 seedKb，覆盖旧数据。

## 第 2 处：情感分析 prompt（5 分钟）

`agents/review-analyzer/index.js` 里搜「口味」「菜品」等餐饮词，换成行业词：

- 餐饮：口味/分量/上菜速度 → 花店：新鲜度/花材搭配/配送时效
- 场景四分法不变，只是关键词表换一组

## 第 3 处：券类型命名（5 分钟）

coupons 集合的券是通用的（满减/折扣/无门槛），只需改前端展示文案：

- 「好友券」→ 可保留，或改「闺蜜券」「车主券」
- 面额档位按行业客单价改（餐饮 100/200/300 → 花店 99/199/299）

## 第 4 处：文案平台调性（10 分钟）

`components/ai-copywriter/index.js` 里四个平台的风格描述，按行业受众微调即可，结构不动。

## 不建议改的部分

- **审批闸门逻辑**（retention-pilot）：与行业无关，动了就丢合规底线
- **agentLog 留痕结构**：改了会影响审计和复盘
- **场景四分法的「只推一条」原则**：这是防轰炸体验的核心

## 复刻检查清单

- [ ] kb 集合里旧行业数据已清空
- [ ] 情感分析能正确识别新行业的差评关键词（手测 3 条假评价）
- [ ] 券面额符合新行业客单价
- [ ] 生成的文案读起来不像另一个行业（让同行朋友看一眼）

完成以上，你就有了一套属于自己行业的营销闭环 Agent。
